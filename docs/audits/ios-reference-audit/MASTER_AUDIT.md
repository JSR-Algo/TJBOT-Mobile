# TJBot-mobile iOS Reference Library Audit — Master Report

## Executive Summary

- **Total findings:** 153
  - Improvements: 75
  - Simplifications: 37
  - Bottlenecks: 41
- **Reference projects benchmarked:** 35+ iOS / React Native reference cards across the 8 areas.
- **Highest-risk themes:** The codebase ships a large amount of unreachable code (orphaned Gemini Live voice UI, unwired XState machines, legacy screen trees) while several production configuration paths are silently misaligned (`eas.json` env keys do not match `src/config.ts`, the fallback API root is a hardcoded Cloudflare tunnel, and the realtime WebSocket URL is derived from the HTTP base URL). At the same time, the auth/network layer is duplicated between `src/services/http/client.ts` and `src/services/api/ai.ts`, and key CI quality gates are either stubs (`scripts/check-api-contract-sync.mjs`) or currently failing (`npm test` reports 9 failed suites). Together these create a high risk of shipping untested code, production misconfiguration, and stranded user sessions.

## Cross-Cutting Themes

### 1. State machines exist but are not wired to the UI
- **Pattern:** XState machines are authored, exported, and unit-tested, but production screens use local `useState`/`useEffect` or module-level mutable variables instead.
- **Locations:** `src/state/machines/devicePairing.machine.ts` vs. `src/features/device/pairing/screens/PairSearchScreen.tsx`, `PairWifiScreen.tsx`, `PairConnectingScreen.tsx` (`pairingSession.ts` lines 14–16); `src/state/machines/lessonSession.machine.ts` vs. `src/features/lesson-session/screens/ConnectingScreen.tsx`; `src/state/machines/parentApproval.machine.ts`.
- **Risk:** Two sources of truth for the same flow; timeouts and error semantics defined in the machine are not enforced in the UI, leading to leaked BLE sessions, hung provisioning screens, and untested behavior in production.
- **Umbrella fix:** Either delete the machines and own the imperatives, or drive each flow from a single actor. For pairing specifically, move `pairingSession.ts` mutable state into the existing `devicePairingMachine` actor and rewrite the screens as observers.

### 2. Production configuration is fragmented and silently wrong
- **Pattern:** Build-time environment values are spread across `eas.json`, `src/config.ts`, `src/__env__.ts` (generated by `metro.config.js`), and Detox `launchArgs`, with no single source of truth.
- **Locations:** `eas.json` lines 17–23 (sets `EXPO_PUBLIC_API_BASE_URL` / `EXPO_PUBLIC_DEMO_SCREEN` which `src/config.ts` ignores); `src/config.ts` lines 17–19 (hardcoded Cloudflare tunnel `prerequisite-analysts-luther-review.trycloudflare.com`); `src/services/ws/realtime.ts` lines 23–38 (derives WS root from HTTP URL); `.detoxrc.js` passing `TBOT_API_URL`/`TBOT_AI_URL` while the app reads `src/__env__.ts` generated at bundle time.
- **Risk:** Production builds can target the wrong backend, WebSocket path mismatches can break realtime lesson sessions, and E2E runs can test against a stale bundle.
- **Umbrella fix:** Freeze a canonical env schema (`TBOT_API_URL`, `TBOT_AI_URL`, `WS_URL`), make `src/config.ts` read only `EXPO_PUBLIC_*` or documented `ENV_*` keys, replace `metro.config.js` source-tree mutation with Expo env handling, and add an integration test that asserts mobile/backend WS path parity.

### 3. Auth/network code is duplicated and has coverage gaps
- **Pattern:** Two axios instances implement the same Bearer + 401 refresh logic; the AI instance exposes an auth-invalidated handler that no one registers.
- **Locations:** `src/services/http/client.ts` lines 34–116 vs. `src/services/api/ai.ts` lines 22–75; `src/services/api/ai.ts:18` (`setAiAuthInvalidatedHandler` unused); duplicate secure-storage wrappers in `src/services/storage/secureStore.ts` and `src/services/http/tokens.ts`; `src/api/client.ts`, `src/api/tokens.ts`, `src/api/learning.ts` re-export shims.
- **Risk:** Refresh fixes must be applied twice; AI token expiry does not force the UI back to login; duplicated helpers fragment ownership.
- **Umbrella fix:** Create a single `createAuthenticatedClient({ baseURL })` factory shared by REST and AI, register one auth-invalidated handler in `AuthContext`, consolidate secure-storage helpers, and delete `src/api/*`.

### 4. Orphaned and dead code increases attack surface and maintenance cost
- **Pattern:** Entire subsystems are implemented but unreachable; legacy screens and aliases remain; unused hooks/providers are kept.
- **Locations:** `src/hooks/useGeminiConversation.ts` + `src/components/gemini/*` (no screen imports); `src/app/providers/AppProviders.tsx` / `ThemeProvider.tsx` (unused); `src/hooks/useOfflineSync.ts`, `useStreamingTranscript.ts`, `useVoiceActivity.ts`, `useLatencyBudget.ts`, `LatencyHud.tsx`; `src/screens/dashboard/ParentDashboardScreen.tsx`, `src/screens/learning/*`, `src/app/screens/SpeakScreen.tsx`, `ListenScreen.tsx`, `DevicePairWifiScreen.tsx`; `src/navigation/types.ts` `LegacyMainStackParamList`.
- **Risk:** Dead native modules and hooks ship in the binary, tests give false confidence, and new engineers copy stale patterns.
- **Umbrella fix:** Delete confirmed-dead files; for the Gemini voice layer make a product decision to either wire it to a navigable screen behind a feature gate or remove it and its native modules.

### 5. Long-running native operations lack cancellation, cleanup, and timeouts
- **Pattern:** BLE provisioning, Wi-Fi scan, and Gemini Live connect/playback use mutable cancellation flags rather than real teardown.
- **Locations:** `src/features/device/pairing/screens/PairWifiScreen.tsx:31-75`, `PairConnectingScreen.tsx:34-107`; `src/services/provisioning/espProvisioning.ts:97-116`; `src/hooks/useGeminiConversation.ts` timers and native audio lifecycle.
- **Risk:** Leaked native sessions, orphaned robots after failed backend claims, and stuck voice UI states.
- **Umbrella fix:** Add `useEffect` cleanup that disconnects/stops scans, wrap native provisioning in a cancelable contract, and wire the existing XState machine timeouts to the UI.

### 6. Animation and visual primitives are duplicated and JS-thread-bound
- **Pattern:** The app has two competing visual languages (Gemini `SukaAvatar`/`WaveVisualizer` vs. lesson-session `Robot`/`WaveBars`/`RobotFace`), many animations use JS `Animated`, and heavy components recreate timers/values on every render.
- **Locations:** `src/components/gemini/WaveVisualizer.tsx`, `SukaAvatar.tsx`, `ParticleEffect.tsx`; `src/components/robot/RobotFace.tsx`, `RobotAnimations.ts`, `RobotBody.tsx`; `src/design-system/components/WaveBars/index.tsx`, `Robot/index.tsx`, `LCDFace/index.tsx`.
- **Risk:** Frame drops on lower-end devices, inconsistent feel, duplicated accessibility labels, and mixed theming.
- **Umbrella fix:** Consolidate on one avatar and one waveform primitive; rewrite the hottest components (`WaveVisualizer`, `SukaAvatar`, `ParticleEffect`) as Reanimated worklets; migrate `RobotFace`/`RobotBody` to the same engine.

### 7. CI and test gates do not match reality
- **Pattern:** Quality gates report success while doing nothing or while the test baseline is red.
- **Locations:** `.github/workflows/ci.yml:79` running `scripts/check-api-contract-sync.mjs` (stub that exits 0); `scripts/api-contract-sync.mjs` default OpenAPI path is a broken symlink; `tests/navigation/route-coverage-script.test.ts:14-16` expects stale counts; `npm test` shows 9 failed suites; no Jest coverage thresholds.
- **Risk:** Regressions slip through; developers learn to ignore CI; the team optimizes for green checkmarks instead of real quality.
- **Umbrella fix:** Bring `npm test` to green, replace the stub contract gate with the real script or delete it, add coverage thresholds, and split docs-integrity checks into a separate workflow.

## Findings by Area

### 1. Project Health
- **Total findings:** 21 (11 Improvements / 5 Simplifications / 5 Bottlenecks)
- **Top 3:**
  1. `eas.json` lines 17–23 sets `EXPO_PUBLIC_API_BASE_URL`/`EXPO_PUBLIC_DEMO_SCREEN`, but `src/config.ts` reads `TBOT_API_URL`/`TBOT_AI_URL`; production EAS builds silently fall back to the hardcoded Cloudflare URL.
  2. `react-native.config.js` lines 24–31 opts `react-native-ble-plx` out of Android autolinking, disabling BLE on Android—a core robot-pairing flow.
  3. `metro.config.js` lines 31–49 parses `.env` and writes `src/__env__.ts` at load time, dirtying git, racing in CI/EAS, and causing stale env values in cached bundles.
- **Full report:** [`reports/project-health.md`](./reports/project-health.md)

### 2. BLE Provisioning
- **Total findings:** 18 (9 Improvements / 4 Simplifications / 5 Bottlenecks)
- **Top 3:**
  1. `src/services/ble/permissions.ts:5-7` returns `'granted'` unconditionally on iOS, so Bluetooth-off/denied users see silent scan failures.
  2. `src/features/device/pairing/pairingSession.ts:14-16` stores `activeCandidate`/`connectedDevice` as mutable module variables, risking corruption across process death and concurrent flows.
  3. `src/services/provisioning/espProvisioning.ts:97-116` + `PairConnectingScreen.tsx:51-101` run provisioning as a single uncancelable native promise; navigating back leaves the native operation running and can orphan the robot.
- **Full report:** [`reports/ble-provisioning.md`](./reports/ble-provisioning.md)

### 3. Audio / Voice
- **Total findings:** 15 (5 Improvements / 5 Simplifications / 5 Bottlenecks)
- **Top 3:**
  1. The entire Gemini Live UI layer (`useGeminiConversation.ts`, `src/components/gemini/*`, custom native modules) is implemented but unreachable—roughly 3,500 lines of dead code and native surface area.
  2. `src/services/ai/safety/README.md` documents a complete child-safety system, but the directory contains only the README; there is no deterministic input/output guard.
  3. `useGeminiConversation.ts` is a 1,560-line monolithic hook with ~40 refs, 14-state FSM timers, and native audio/SDK wiring, making it extremely hard to test and reason about.
- **Full report:** [`reports/audio-voice.md`](./reports/audio-voice.md)

### 4. State Architecture
- **Total findings:** 19 (7 Improvements / 6 Simplifications / 6 Bottlenecks)
- **Top 3:**
  1. `devicePairingMachine`, `parentApprovalMachine`, and `lessonSessionMachine` are exported and tested, but no production code imports `createActor`/`useMachine`; screens implement the same flows imperatively.
  2. `src/services/api/ai.ts` duplicates the token-refresh interceptor from `src/services/http/client.ts` and exposes an unregistered `setAiAuthInvalidatedHandler`, leaving AI-session expiry unhandled.
  3. `HouseholdContext.tsx` lines 64–103 manually fetches server state instead of using React Query, blocking the cold start on sequential API calls with no mutation invalidation.
- **Full report:** [`reports/state-architecture.md`](./reports/state-architecture.md)

### 5. Network / Auth / WebSocket
- **Total findings:** 21 (11 Improvements / 5 Simplifications / 5 Bottlenecks)
- **Top 3:**
  1. `src/services/ws/realtime.ts:23-38` derives the observer WebSocket URL from the HTTP base URL with fragile path stripping/appending—the likely source of the documented mobile/backend WebSocket path contract mismatch.
  2. Two axios instances (`client` and `_aiClient`) duplicate Bearer + 401 refresh logic; fixes must be applied in two places and error normalization already diverges.
  3. `src/services/ws/realtime.ts:105-112` and `xiaozhi-device.ts:102-103` replace original WebSocket `Error`/`CloseEvent` data with generic strings, removing the codes/reasons needed for production debugging.
- **Full report:** [`reports/network-auth-ws.md`](./reports/network-auth-ws.md)

### 6. Navigation & Screens
- **Total findings:** 14 (7 Improvements / 3 Simplifications / 4 Bottlenecks)
- **Top 3:**
  1. `src/screens/*` contains a dead legacy screen tree (`ParentDashboardScreen.tsx`, `ChildPracticeScreen.tsx`, `LessonPlannerScreen.tsx`) with stale route names not in `RootStackParamList`.
  2. `ModalNavigator.tsx` lines 29, 55–74 mounts five independent `MainTabNavigator` instances (one per tab), bloating memory and complicating deep-link state handling.
  3. `src/navigation/linking.ts` and `AppNavigator.tsx` silently drop unknown deep links with no logging or fallback screen.
- **Full report:** [`reports/navigation-screens.md`](./reports/navigation-screens.md)

### 7. UI / Design System
- **Total findings:** 24 (13 Improvements / 4 Simplifications / 7 Bottlenecks)
- **Top 3:**
  1. Two parallel token systems exist: low-level `src/design-system/tokens/*.ts` and older `src/design-system/tokens/legacy-semantic.ts`; production components mostly import the legacy file, creating a two-authority problem.
  2. `WaveVisualizer.tsx`, `SukaAvatar.tsx`, and `ParticleEffect.tsx` create many `Animated.Value`s and timers on every render, risking frame drops on lower-end devices.
  3. There is no central icon library; inline SVGs and emoji glyphs (`CircleBtn`, `PageHeader`, `DeviceRow`, `BigMicButton`, `ErrorMessage`, `EmptyState`) hurt accessibility and cross-platform consistency.
- **Full report:** [`reports/ui-design-system.md`](./reports/ui-design-system.md)

### 8. Testing & Quality
- **Total findings:** 21 (12 Improvements / 5 Simplifications / 4 Bottlenecks)
- **Top 3:**
  1. `scripts/check-api-contract-sync.mjs` is a 5-line stub that always exits 0, so the CI contract-sync gate passes without verifying backend/mobile drift.
  2. `npm test` currently reports 9 failed suites, including a broken `openapi.json` symlink and stale route-coverage expectations.
  3. `tests/hooks/useGeminiConversation-p0.test.ts` and `bargein-ordering.test.ts` are mostly source-file regex assertions, making them brittle to any refactor.
- **Full report:** [`reports/testing-quality.md`](./reports/testing-quality.md)

## Quick Wins (low effort, high value)

1. **Align EAS production env keys with `src/config.ts`.** `eas.json` uses `EXPO_PUBLIC_*` keys the app never reads; production builds silently fall back to the hardcoded Cloudflare URL (`project-health`).
2. **Remove stale project-hygiene debt.** Delete the duplicate `build`/`typecheck` scripts, remove the stale `expo-av` Jest mapper, and scope the `no-require-imports` ESLint override to config files only (`project-health`).
3. **Expand Jest `transformIgnorePatterns`.** Whitelist the ESM packages actually used at runtime (`@orbital-systems`, `@google/genai`, `lucide-react-native`, etc.) so unit tests stop failing on untransformed imports (`project-health`).
4. **Memoize `AuthContext` and `HouseholdContext` provider values.** This mirrors `ParentSessionContext` and immediately reduces re-render cascades near the root (`state-architecture`).
5. **Cap the voice message array in `voiceAssistantStore.addMessage`.** Long sessions currently append without bound, risking memory pressure and slow transcript re-renders (`state-architecture`).
6. **Delete confirmed-dead wrappers and shims.** Remove `AppProviders.tsx`, `ThemeProvider.tsx`, `src/api/*` re-export shims, and unused hooks (`useOfflineSync`, `useStreamingTranscript`, `useVoiceActivity`, `useLatencyBudget`, `LatencyHud`) (`state-architecture`, `network-auth-ws`).
7. **Delete legacy navigation artifacts.** Remove `src/screens/*`, `src/app/screens/*`, and `LegacyMainStackParamList` from `src/navigation/types.ts` (`navigation-screens`).
8. **Fix BLE scan basics.** Check real iOS Bluetooth state in `src/services/ble/permissions.ts`, bump scan timeout to 30 s to match the machine spec, and capture/sort candidates by RSSI (`ble-provisioning`).
9. **Clean up BLE sessions on unmount.** Call `device.disconnect()` and `stopProvisionSearch()` in the `useEffect` cleanup of `PairWifiScreen.tsx` and `PairConnectingScreen.tsx` (`ble-provisioning`).
10. **Replace `Vibration` with `expo-haptics` in `Pressable.tsx`.** `expo-haptics` is already a dependency; this gives proper iOS haptics and respects accessibility (`ui-design-system`).
11. **Harden `ReconnectingOverlay` timeout cleanup.** Clear the 2400 ms timer on `beforeRemove` so it cannot navigate away from a later screen (`navigation-screens`).

## Reference Library Highlights

- **pointfreeco/swift-composable-architecture** — strongest contrast for state architecture: strict `State → Action → Reducer → Effect` boundaries, dependency injection, and testable reducers. Directly applicable to TJBot’s unwired XState machines and the monolithic `useGeminiConversation.ts`.
- **element-hq/element-x-ios** — best reference for auth/network lifecycle: a single shared client with serialized token refresh, keychained restoration tokens, and auth invalidation as a first-class state transition. Also informs navigation coordinators and deep-link dispatch.
- **jellyfin/Swiftfin** — useful for separating server state (`CoreStore`), settings (`Defaults`), and credentials (`KeychainSwift`), and for navigation coordinator patterns.
- **AudioKit/Waveform** — demonstrates GPU/Metal-backed waveform rendering and precomputed level-of-detail buffers, contrasting with TJBot’s JS `Animated.timing` per-bar approach.
- **argmaxinc/argmax-oss-swift / soniqo/speech-swift / FluidAudio** — show on-device ASR/VAD/TTS pipelines using CoreML/ANE and actor isolation, highlighting the risk of TJBot’s full-cloud Gemini Live dependency.
- **Espressif `esp-idf-provisioning-ios`** — the canonical ESP32 onboarding SDK: prefix filtering, encrypted sessions, proof-of-possession, transport abstraction, and Wi-Fi join polling. TJBot’s dual BLE/ESP provisioning libraries and single-attempt connect logic fall short of this benchmark.
- **adessoTurkey/ios-sample-app-swiftui** — illustrates clean CI discipline (Maestro, SwiftLint, git hooks) and a single project generator, contrasting with TJBot’s 61-file `scripts/` sprawl and misleading CI gates.
