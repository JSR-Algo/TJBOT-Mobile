# ERD Conventions — DBML + Entity Markdown

Naming, typing, and FK rules for every `*.dbml` and `*.md` file under `docs/erd/`. Mirrors the lane discipline of `docs/sequences/`. **Frozen 2026-05-12 (Phase 1).**

Files that violate these rules fail `npm run erd:fast` (see `scripts/erd/validate-erd.mjs`).

## 1. Identifier types

- All primary keys are `uuid` generated by the owning service. **No `serial` / `bigserial`** — replication-safe IDs only.
- Every table includes both `created_at timestamptz` and `updated_at timestamptz` on every table. Immutable rows leave `updated_at` equal to `created_at` (do not omit the column).
- Soft-delete is signalled by a nullable `deleted_at timestamptz` column **only** on entities with an explicit COPPA/GDPR retention window. Retention must be declared in the entity markdown frontmatter (`retention:`).
- Hard-delete is declared in the entity markdown (`Lifecycle.Delete = hard`) and must reference a retention spec or runbook.

## 2. Status enums + state machines

- Status enums are declared inline in DBML with `enum`, named `<entity>_status` — e.g. `session_status`, `ota_release_status`, `deletion_job_status`.
- Entities with a status enum MUST also declare `state_machine:` in entity-markdown frontmatter pointing at the relevant state-machine doc, system spec, or `@inline` (transitions captured in the entity .md body).

## 3. Foreign keys

- Foreign keys are declared as explicit `Ref:` lines at the bottom of the DBML file. **No inline `[ref:]` shorthand** — explicit lines are easier to diff and grep.
- Cross-domain FKs are declared in the **owning** entity file (the side that owns the target table), with a comment `// cross-domain ref → OwnerService`. The consuming side carries only the column.
- Every `Ref:` must resolve to an existing column elsewhere in the ERD (enforced by `fk-reachable`).

## 4. Indexes + uniqueness

- Indexes are named `idx_<table>_<columns>_<purpose>` — e.g. `idx_sessions_household_id_status_active`.
- Composite indexes cite the motivating hot query in a DBML `Note:` comment referencing a sequence file (e.g. `// hot query: docs/sequences/04-realtime/session-close.sequence.mmd`).
- Unique constraints live in a separate `Indexes { (col_a, col_b) [unique] }` block, never inline on the column.

## 5. Scalar typing

- All `varchar` fields specify a length. `varchar(254)` for email (RFC 5321). `varchar(64)` for slugs. `varchar(2048)` for URLs.
- Timestamps are always `timestamptz` — never `timestamp` (naive). Backend stores UTC.
- Money is `bigint` cents. **Never `numeric`, `decimal`, or `float`** for currency.
- **Sub-cent exception** (amended 2026-05-12 in Phase 3): `bigint` **micros** (millionths of a unit) is permitted when the column requires sub-cent precision — e.g. per-LLM-call cost attribution where a single call can cost $0.000045. The column MUST carry an explicit DBML `Note:` declaring the unit (e.g. `'USD micros — 1_000_000 micros = $1.00'`) so emission tooling and downstream consumers cannot mis-scale. Default for all other money fields remains `bigint cents`. Precedent: Lane D LLM cost columns.
- Booleans default to `false` unless tri-state semantics are required (then nullable `boolean`).
- Free-text fields default to `text` (no length cap) unless a hard upper bound exists.
- JSON payloads use `jsonb` (never `json`). Document the shape in the entity `.md` body.

## 6. File layout per entity

- One `.dbml` file per entity, named `<table_name>.dbml`.
- One sibling `<table_name>.md` per `.dbml`, with the frontmatter described in `templates/entity.md`.
- Folder `README.md` per system lists every entity with a one-line purpose.
- `_shared/` for cross-cutting tables; `_global/` for assembled artefacts only.

## 7. Annotations (validator-aware)

- `@stateless` in entity-markdown frontmatter waives `entity-has-timestamps` and `entity-md-sequences-referenced` (use sparingly, e.g. ephemeral admin lookups with no audit need).
- `@no-sequence` waives `entity-md-sequences-referenced` for entities that exist before sequences are written (rare).
- `@timescaledb-hypertable(column=<ts_col>, interval='<window>')` in a DBML `Note:` declares a TimescaleDB hypertable; emission tooling reads this later.

## 8. Money / time / id summary table

| Concept | DBML type | Rationale |
|---|---|---|
| Primary key | `uuid` | replication-safe, opaque |
| Email | `varchar(254)` | RFC 5321 |
| URL | `varchar(2048)` | practical max |
| Money | `bigint` (cents) | no rounding drift |
| Money (sub-cent) | `bigint` (micros) | per-LLM-call cost — explicit `Note:` declares unit |
| Timestamp | `timestamptz` | UTC + tz |
| Status | `enum <entity>_status` | explicit state machine |
| Free text | `text` | no truncation surprises |
| JSON | `jsonb` | indexable |

## 9. Anti-patterns (FAIL on review)

- `serial` / `bigserial` PK.
- `varchar` without an explicit length.
- `numeric` / `float` for currency (use `bigint cents`, or `bigint micros` with declared unit).
- `timestamp` (naive) for any time field.
- Inline `[ref:]` instead of explicit `Ref:` line.
- Entity .dbml without sibling .md, or vice versa.
- Frontmatter missing `entity`, `domain`, `service_owner`, `retention`.
- Cross-domain FK declared on the consuming side instead of the producer side.
- Composite index with no justifying sequence reference.
