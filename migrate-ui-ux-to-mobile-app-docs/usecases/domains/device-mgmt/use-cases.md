## UC-DM01 — View Device Home

- **Goal:** Parent gets a dashboard view of the paired Robot — online state, today's lesson, quick actions (chime, quiet hours, sync, firmware).
- **Trigger:** Navigation arrives at `dv_home` (`DeviceHomePage`).
- **Preconditions:** Parent passed UC-PR01; a Robot is paired (UC-DP10 completed at some prior point).
- **Main Flow:**
  1. `DeviceHomePage` mounts and renders the hero card with Robot status (Online · idle, battery %, Wi-Fi) — `DeviceHomeScreen.jsx:11-24`.
  2. Page renders the "Today" summary (current Unit/Lesson, words to revisit, yesterday's stats) — `DeviceHomeScreen.jsx:27-35`.
  3. Page renders the Robot quick-action list (chime / quiet hours / sync / firmware) — `DeviceHomeScreen.jsx:38-46`.
  4. Parent taps a quick-action row → routes to UC-DM02/DM03/DM04 or related.
- **Postconditions:** Parent has a current snapshot of Robot health; navigation may transition to a sub-detail screen.
- **Alt Flow:**
  1. Parent taps "Lesson 4 of 6 · Start" → `dv_session` (UC-DM02) — `DeviceHomeScreen.jsx:31`.
  2. Parent taps "Yesterday: 1 lesson" → cross-domain handoff to progress (see cross-domain-edges.json).

## UC-DM02 — View Live Session Monitor

- **Goal:** Parent watches a live mirror of what Robot is doing right now (LCD state, current lesson, progress, quick controls).
- **Trigger:** Parent taps the in-progress lesson row on UC-DM01, landing on `dv_session` (`DeviceSessionPage`).
- **Preconditions:** Robot is online and a lesson is in progress (UI-only loop in the prototype).
- **Main Flow:**
  1. `DeviceSessionPage` mounts a 2.2 s LCD-state loop demo (listen → think → speak → success) — `DeviceSessionScreen.jsx:8-15`.
  2. Page renders the live LCD card, the "Now playing" Unit/Lesson card with progress bar, and a row list (lower volume / pause Robot / end lesson) — `DeviceSessionScreen.jsx:19-45`.
  3. Parent observes; may tap a control row to influence Robot.
- **Postconditions:** Parent has a live read of session state; may have lowered volume / paused / ended (prototype controls are static).
- **Alt Flow:**
  1. Parent taps back → returns to `dv_home` (UC-DM01).

## UC-DM03 — Find My Robot

- **Goal:** Parent makes Robot play a soft chime so they can locate it physically.
- **Trigger:** Parent taps "Make Robot chime" on UC-DM01 quick actions, landing on `dv_lost` (`DeviceLostPage`).
- **Preconditions:** Robot is paired and online (last-seen banner shows a recent timestamp).
- **Main Flow:**
  1. `DeviceLostPage` shows Robot illustration + last-seen + probable-room cards (`DeviceLostScreen.jsx:11-32`).
  2. Parent taps "Make Robot chime" → toggles `chiming=true` and triggers a 30 s pulse animation (`DeviceLostScreen.jsx:36`).
  3. Robot plays a chime (cross-domain delegate to Robot Device hardware — see cross-domain-edges.json: UC-DM03→ACTOR:Robot).
  4. Parent taps "Stop chime" or waits for the 30 s timeout — chime ends.
- **Postconditions:** Parent located Robot (or did not — UI offers to retry).

## UC-DM04 — Update Firmware

- **Goal:** Parent reviews the available Robot firmware update (size, ETA, changelog) and schedules / starts the install.
- **Trigger:** Parent taps the Firmware row on UC-DM01 quick actions (when an update banner is present), landing on `dv_firmware` (`DeviceFirmwarePage`).
- **Preconditions:** Robot is paired and online; a newer firmware version is available (prototype hardcodes "v1.5.0 · 24 MB").
- **Main Flow:**
  1. `DeviceFirmwarePage` shows the version + size + ETA card and a "What's new" changelog list (`DeviceFirmwareScreen.jsx:11-32`).
  2. Parent picks "Update tonight (recommended)" or "Update now" (`DeviceFirmwareScreen.jsx:36-37`).
  3. App schedules / starts OTA via `device.api.js → runFirmwareUpdate` (cross-domain delegate to Robot — see cross-domain-edges.json: UC-DM04→ACTOR:Robot).
  4. Navigation returns to `dv_home`.
- **Postconditions:** Update is scheduled or running; Robot will be unavailable for ~4 minutes during install.
- **Error Flow:**
  1. OTA failure → Parent re-enters UC-DM04 to retry (no dedicated failure screen in the prototype).

## UC-DM05 — View LCD Face Library

- **Goal:** Designer / parent browses the catalog of 20 LCD faces grouped by purpose (Conversation / Feedback / System / Safety / Lifecycle) — primarily a design-review surface.
- **Trigger:** Navigation arrives at `dv_lcd_lib` (`LCDLibraryPage`); typically reachable from a designer/dev nav menu.
- **Preconditions:** None (page is informational).
- **Main Flow:**
  1. `LCDLibraryPage` mounts and renders the header "20 faces, one warm character" (`LCDLibraryScreen.jsx:14-21`).
  2. Page iterates `LCD_STATES_LIST` grouped into 5 categories (`LCDLibraryScreen.jsx:7-11`).
  3. Each face renders via `<LCDFace>` — viewer scans the catalog for design QA.
- **Postconditions:** Viewer has reviewed the face catalog; no state mutation.
- **Alt Flow:**
  1. Viewer navigates to UC-DM06 (One Lesson Turn) for the in-context demo.

> **KD6 cross-ref:** UC-DM05 + UC-DM06 share Robot's LCD renderer with `robot-mgmt`. The LCD UCs live in this domain; see `robot-mgmt/use-cases.md` top-of-file note.

## UC-DM06 — View One Lesson Turn

- **Goal:** Designer / parent sees the 5-state speak → listen → child-speak → think → celebrate sequence Robot uses in every lesson turn.
- **Trigger:** Navigation arrives at `dv_lcd_turn` (`LCDLessonTurnPage`).
- **Preconditions:** None (page is informational).
- **Main Flow:**
  1. `LCDLessonTurnPage` renders the 5-step turn (speak / listen / child speak / think / celebrate) with caption + dialogue + duration per step (`LCDLessonTurnScreen.jsx:6-13`).
  2. Each step renders the appropriate `<LCDFace>` state.
  3. Viewer scans the sequence for design QA.
- **Postconditions:** Viewer understands one canonical lesson turn; no state mutation.
