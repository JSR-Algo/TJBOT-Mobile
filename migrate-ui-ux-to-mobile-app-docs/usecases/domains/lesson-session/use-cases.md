## UC-L01 — Start Voice Session

- **Goal:** Child initiates the daily voice activity loop with Robot.
- **Trigger:** Child taps "I'm ready!" CTA on `LessonReadyPage` (`LessonReadyScreen.jsx:25`).
- **Preconditions:** Child has selected today's lesson (via UC-H03, UC-C05, UC-C06, UC-C07, or UC-C08); microphone permission granted (UC-O03); voice service reachable.
- **Main Flow:**
  1. Child sees today's lesson title and Robot avatar with "Wear headphones if you can" hint.
  2. Child taps "I'm ready!" → navigation transitions to `connecting`.
  3. UC-L02 (Connect to Realtime Voice) runs as an `<<include>>` step (per `lesson-session.usecase.puml:53`).
  4. On connect success, UC-L03 (Receive Robot Greeting) runs.
- **Postconditions:** Lesson store has `sessionId` set via `useLessonStore.start()`; navigation lands on `greeting`. The voice activity loop is now active.
- **Alt Flow:**
  1. Child taps the exit (X) button → UC-L17 Confirm Exit Lesson.
- **Error Flow:**
  1. Voice connect failure → UC-L19 Recover from Audio Error.

## UC-L02 — Connect to Realtime Voice

- **Goal:** Establish the realtime voice transport so Robot can speak and listen.
- **Trigger:** UC-L01 transitioned to `connecting` (`LessonReadyScreen.jsx` → `go('connecting')`).
- **Preconditions:** `useLessonStore.sessionId` is being created; microphone permission granted; `openRealtime` observer transport exists in `src/services/ws/realtime.{ts,js}`; production provider/sessionId auto-attach is NOT CONFIRMED in source (KD10).
- **Main Flow:**
  1. `ConnectingScreen` renders the connecting indicator (`src/features/lesson-session/screens/ConnectingScreen.tsx`).
  2. Client attaches the mobile observer lane via `src/services/ws/realtime.{ts,js} → openRealtime` when a production `sessionId` is available.
  3. Voice observer channel reaches "open" state — connection delegated to external service (see cross-domain-edges.json: UC-L02→ACTOR:RealtimeVoiceService).
  4. Client navigates to `greeting` only after observer/open evidence or an explicit offline fallback path; legacy timer-only auto-advance is not production evidence.
- **Postconditions:** Voice observer transport is open or a recoverable fallback state is active; navigation lands on `greeting`; `useLessonStore.lastTurnState` ready for first turn.
- **Error Flow:**
  1. Connection failure or timeout → UC-L19 Recover from Audio Error.

## UC-L03 — Receive Robot Greeting

- **Goal:** Robot opens the session warmly so the child feels welcomed before any task.
- **Trigger:** UC-L02 success transitions `connecting → greeting`.
- **Preconditions:** Voice transport open; `useLessonStore.sessionId` set.
- **Main Flow:**
  1. `GreetingScreen` renders Robot in greet emotion with the opening line.
  2. Robot speaks the greeting via voice transport (delegated, see cross-domain-edges.json: UC-L03→ACTOR:RealtimeVoiceService).
  3. Child taps "Yes, let's go!" CTA (`GreetingScreen.jsx`) → navigation transitions to `activity_intro` → UC-L04.
- **Postconditions:** Navigation lands on `activity_intro`; child has acknowledged the start.
- **Alt Flow:**
  1. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L04 — Begin Activity

- **Goal:** Robot frames the first activity so the child knows what they will do.
- **Trigger:** UC-L03 child taps "Yes, let's go!".
- **Preconditions:** Greeting completed; `useLessonStore.activityIndex === 0`.
- **Main Flow:**
  1. `ActivityIntroScreen` renders the activity title and Robot in intro pose (`ActivityIntroScreen.jsx`).
  2. Child taps "Start" CTA (`ActivityIntroScreen.jsx:5`) → navigation transitions to `robot_speaking` → UC-L05.
- **Postconditions:** Activity is framed; navigation lands on `robot_speaking`.
- **Alt Flow:**
  1. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L05 — Listen to Robot Speech

- **Goal:** Child hears Robot's prompt or model utterance for the current turn.
- **Trigger:** Activity began (UC-L04) OR previous turn completed (UC-L09 Next, UC-L10 try-again, UC-L11 retry, etc).
- **Preconditions:** Voice transport open; turn state is `robot_speaking`.
- **Main Flow:**
  1. `RobotSpeakingScreen` renders Robot in speaking emotion (`RobotSpeakingScreen.jsx`).
  2. Robot streams the prompt audio over the voice transport (delegated, see cross-domain-edges.json: UC-L05→ACTOR:RealtimeVoiceService).
  3. On TTS-end signal (or user tap of "skip" button), navigation transitions to `robot_listening` → UC-L06.
- **Postconditions:** Robot's audio finished; navigation lands on `robot_listening`.
- **Alt Flow:**
  1. Child taps exit (X) → UC-L17 Confirm Exit Lesson.
  2. Child interrupts Robot mid-speech → UC-L14 Handle Barge-in.

## UC-L06 — Listen for Child Speech

- **Goal:** Robot waits for the child to speak, with a visible mic affordance.
- **Trigger:** Robot's prompt finished (UC-L05) OR recovery returns the loop to listening (UC-L18, UC-L19).
- **Preconditions:** Voice transport open; turn state is `robot_listening`.
- **Main Flow:**
  1. `RobotListeningScreen` renders Robot in listening emotion with a Mic button (`RobotListeningScreen.jsx`).
  2. Voice transport opens the inbound audio channel and the VAD watches for speech.
  3. Child taps the Mic button (`RobotListeningScreen.jsx`) OR VAD detects speech → navigation transitions to `user_speaking` → UC-L07.
- **Postconditions:** Inbound audio is being captured; navigation lands on `user_speaking`.
- **Alt Flow:**
  1. Child stays silent past the silence threshold → UC-L12 Receive Silence Prompt.
  2. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L07 — Record Child Utterance

- **Goal:** Capture the child's spoken response and forward it for processing.
- **Trigger:** UC-L06 detected speech start.
- **Preconditions:** Inbound audio channel open; `useLessonStore.lastTurnState === 'user_speaking'`.
- **Main Flow:**
  1. `UserSpeakingScreen` renders the active mic button with "stop" affordance (`UserSpeakingScreen.jsx`).
  2. Voice transport streams the child's audio to the realtime service (see cross-domain-edges.json: UC-L07→ACTOR:RealtimeVoiceService).
  3. VAD detects speech-end OR child taps "stop" Mic button → navigation transitions to `thinking` → UC-L08.
- **Postconditions:** Child utterance bytes have been forwarded; navigation lands on `thinking`.
- **Alt Flow:**
  1. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L08 — Process Utterance

- **Goal:** Robot processes the child's utterance and decides which feedback branch to take.
- **Trigger:** UC-L07 sent the utterance.
- **Preconditions:** Realtime voice service has the audio; `useLessonStore.lastTurnState === 'thinking'`.
- **Main Flow:**
  1. `ThinkingScreen` renders Robot in thinking emotion.
  2. Voice service runs ASR + grading (delegated, see cross-domain-edges.json: UC-L08→ACTOR:RealtimeVoiceService).
  3. Service returns one of: match → UC-L09; near → UC-L10; miss → UC-L11; timeout → UC-L12; offtopic → UC-L13 (per `lesson-session.usecase.puml:57-61`).
  4. Client navigates to the corresponding feedback screen.
- **Postconditions:** Branch decision recorded; navigation lands on the chosen feedback state.
- **Alt Flow:**
  1. Safety classifier flags the utterance → UC-L20 Trigger Safety Fallback.

## UC-L09 — Receive Success Feedback

- **Goal:** Child gets clear positive reinforcement after a correct response.
- **Trigger:** UC-L08 returned `match`.
- **Preconditions:** Turn state is `success`.
- **Main Flow:**
  1. `SuccessScreen` renders Robot in success emotion with the success line (`SuccessScreen.jsx`).
  2. Voice service streams the success audio (delegated, see cross-domain-edges.json: UC-L09→ACTOR:RealtimeVoiceService).
  3. Child taps "Next →" CTA → navigation transitions to `robot_speaking` for the next turn (UC-L05).
- **Postconditions:** Success counter incremented in lesson store; navigation lands on `robot_speaking`.
- **Alt Flow:**
  1. If this was the final activity turn → UC-L15 Complete Activity.
  2. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L10 — Receive Gentle Correction

- **Goal:** Child hears a non-blaming correction so they can model the right answer.
- **Trigger:** UC-L08 returned `near` (close but not exact).
- **Preconditions:** Turn state is `gentle`.
- **Main Flow:**
  1. `GentleScreen` renders Robot in gentle emotion with the corrected model line (`GentleScreen.jsx`).
  2. Voice service streams the correction audio (delegated, see cross-domain-edges.json: UC-L10→ACTOR:RealtimeVoiceService).
  3. Child taps "Try again" → navigation transitions to `robot_listening` → UC-L06.
- **Postconditions:** Navigation lands on `robot_listening`; turn loop continues.
- **Alt Flow:**
  1. Child taps "skip" affordance → navigation to `robot_speaking` to advance prompt.
  2. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L11 — Receive Retry Prompt

  2. Voice service streams the retry audio (delegated, see cross-domain-edges.json: UC-L11→ACTOR:RealtimeVoiceService).

## UC-L12 — Receive Silence Prompt

- **Goal:** Robot nudges the child when they stay silent past the threshold.
- **Trigger:** UC-L08 returned `timeout` OR UC-L06 silence-watchdog fired.
- **Preconditions:** Turn state is `silence`.
- **Main Flow:**
  1. `SilenceScreen` renders Robot in coaxing emotion with "I'm here when you're ready" line (`SilenceScreen.jsx`).
  2. Voice service streams the silence-prompt audio (delegated, see cross-domain-edges.json: UC-L12→ACTOR:RealtimeVoiceService).
  3. Child taps "I'm here!" CTA → navigation transitions to `robot_listening` → UC-L06.
- **Postconditions:** Silence counter incremented; navigation lands on `robot_listening`.
- **Alt Flow:**
  1. Repeated silence (≥ 3 cycles) → escalate to UC-L19 Recover from Audio Error to suggest mic check.
  2. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L13 — Receive Off-topic Redirect

- **Preconditions:** Turn state is `offtopic`.
- **Main Flow:**
  1. `OfftopicScreen` renders Robot in gentle redirect pose (`OfftopicScreen.jsx`).
  2. Voice service streams the redirect audio (delegated, see cross-domain-edges.json: UC-L13→ACTOR:RealtimeVoiceService).
  3. Child taps "Back to the cat" CTA → navigation transitions to `robot_listening` → UC-L06.
- **Postconditions:** Off-topic counter incremented; navigation lands on `robot_listening`.
- **Alt Flow:**
  1. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L14 — Handle Barge-in

- **Goal:** Voice loop accepts the child interrupting Robot mid-speech without losing the turn.
- **Trigger:** Child speech detected during UC-L05 (Robot speaking) per `lesson-session.usecase.puml:46`.
- **Preconditions:** Voice transport open; turn state is `robot_speaking` and VAD detects speech-start.
- **Main Flow:**
  1. Voice service detects barge-in → emits barge-in event.
  2. `BargeinScreen` renders Robot pausing with mic prompt (`BargeinScreen.jsx`).
  3. Child taps Mic button → navigation transitions to `thinking` → UC-L08 processes the bargein utterance.
- **Postconditions:** Robot's prior audio truncated; turn re-routes through processing.
- **Alt Flow:**
  1. False positive (no real utterance) → fall back to `robot_listening` for normal turn.
  2. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L15 — Complete Activity

- **Goal:** Child sees a clear "this activity is done" celebration before next.
- **Trigger:** Final turn of an activity completed via UC-L09 success path.
- **Preconditions:** All scripted turns of the activity have run; turn state is `activity_done`.
- **Main Flow:**
  1. `ActivityDoneScreen` renders activity-completion celebration (`ActivityDoneScreen.jsx`).
  2. Lesson store advances activity index via `useLessonStore.nextActivity()`.
  3. Child taps "Keep going →" CTA → navigation transitions to `robot_speaking` for next activity (UC-L05).
- **Postconditions:** `useLessonStore.activityIndex` incremented; navigation lands on `robot_speaking`.
- **Alt Flow:**
  1. If this was the final activity in the lesson → UC-L16 Complete Lesson.
  2. Child taps exit (X) → UC-L17 Confirm Exit Lesson.

## UC-L16 — Complete Lesson

- **Goal:** Child sees the lesson finale and is offered the summary or a way home.
- **Trigger:** UC-L15 completed the final activity.
- **Preconditions:** All activities done; turn state is `lesson_done`.
- **Main Flow:**
  1. `LessonDoneScreen` renders the "You did it!" finale with star count and farewell line (`LessonDoneScreen.jsx`).
  2. Child taps "See what you did" CTA → navigation transitions to `lesson_summary` (cross-domain handoff to progress, see cross-domain-edges.json: UC-L16→UC-P03).
- **Postconditions:** Lesson session is complete; navigation lands in progress domain (lesson summary).
- **Alt Flow:**
  1. Child taps "Back home" → navigation transitions to `home_hub_idle` (see cross-domain-edges.json: UC-L16→UC-H01).

## UC-L17 — Confirm Exit Lesson

- **Goal:** Speed-bump that confirms the child really wants to stop the lesson before tearing the session down.
- **Trigger:** Child taps the exit (X) button on any in-session screen (`LessonHeader` `onExit`).
- **Preconditions:** Active session — `useLessonStore.sessionId` is non-null.
- **Main Flow:**
  1. `ExitConfirmScreen` renders the dimmed sheet "Stop the lesson? We can finish later." (`ExitConfirmScreen.jsx`).
  2. Child taps "Stop for now" → `useLessonStore.end()` clears session; navigation transitions to `home_hub_idle` (cross-domain handoff, see cross-domain-edges.json: UC-L17→UC-H01).
- **Postconditions:** Session ended; navigation lands on home hub idle.
- **Alt Flow:**
  1. Child taps "Keep playing" → navigation transitions back to `robot_listening` (UC-L06); session continues uninterrupted.

## UC-L18 — Reconnect Voice

- **Goal:** Voice loop self-heals when the realtime transport drops mid-session.
- **Trigger:** Voice transport disconnect detected (heartbeat lost OR socket closed) during any active turn screen.
- **Preconditions:** `useLessonStore.sessionId` non-null; transport state was previously open.
- **Main Flow:**
  1. `ReconnectingScreen` renders the reconnecting indicator (`ReconnectingScreen.jsx`).
  2. Client retries the open-realtime call with bounded backoff.
  3. On success, navigation returns to `robot_listening` → UC-L06 to resume the turn.
- **Postconditions:** Voice transport open again; navigation lands on `robot_listening`.
- **Error Flow:**
  1. Reconnect attempts exhausted → cross-domain handoff to fallback-shell (see cross-domain-edges.json: UC-L18→UC-FB02).

## UC-L19 — Recover from Audio Error

- **Goal:** Child gets a recoverable error path when the local audio stack misbehaves (mic blocked, capture failed) inside a session.
- **Trigger:** Local audio capture error detected during UC-L06/L07 OR upstream service signals audio-failed; OR navigated from UC-L02 connect failure.
- **Preconditions:** Active session; turn state is `audio_error`.
- **Main Flow:**
  1. `AudioErrorScreen` renders Robot in concerned pose with "Try again" CTA (`AudioErrorScreen.jsx`).
  2. Child taps "Try again" → navigation transitions to `robot_listening` → UC-L06.
- **Postconditions:** Navigation lands on `robot_listening`; the loop is given another chance.
- **Alt Flow:**
  1. Child taps "Stop for now" → cross-domain handoff to home (see cross-domain-edges.json: UC-L19→UC-H01).
  2. Persistent audio failure → cross-domain handoff to fallback-shell mic-needed surface (see cross-domain-edges.json: UC-L19→UC-FB04).

## UC-L20 — Trigger Safety Fallback

- **Goal:** Voice loop suspends safely when a safety classifier flags content (per puml `<<include>>` to UC-L21).
- **Trigger:** Safety classifier in voice service raises a flagged event during UC-L08 processing.
- **Preconditions:** Active session; turn state transitions to `safety`.
- **Main Flow:**
  1. `SafetyScreen` renders Robot in calm pose with "Take a break" CTA (`SafetyScreen.jsx`).
  2. UC-L21 Report Safety Event runs as an `<<include>>` step (per `lesson-session.usecase.puml:62`).
  3. Child taps "Take a break" → `useLessonStore.end()` clears session; navigation transitions to `home_hub_idle` (cross-domain handoff, see cross-domain-edges.json: UC-L20→UC-H01).
- **Postconditions:** Session ended; safety event recorded (UC-L21); navigation lands on home hub idle.

## UC-L21 — Report Safety Event

- **Goal:** Persist a safety-flagged event so the parent / moderation team can review it.
- **Trigger:** UC-L20 included this step.
- **Preconditions:** Safety classifier produced a structured event payload.
- **Main Flow:**
  1. (Hypothetical) client posts the event via `lesson-session.api.js → reportSafetyEvent` (currently throws `not implemented`).
  2. On success, the safety event is stored for parent visibility (delegated, see cross-domain-edges.json: UC-L21→ACTOR:RealtimeVoiceService).
- **Postconditions:** Safety event durably recorded server-side. Until backend lands, the call is `BACKEND_NOT_DESIGNED`.
- **Error Flow:**
  1. Report failure must not block UC-L20 returning the child to home — the safety UX path always completes locally even if the report is queued for retry.

## UC-L22 — Lesson Handoff (Parent App → Robot Start)

- **Goal:** Parent (or child via kid-hub) initiates a lesson from the mobile app; backend dispatches to the paired robot which then owns the realtime WebSocket; parent app attaches as a read-only observer. Per ADR-0006.
- **Trigger:** Tap "Start lesson" CTA from `lesson_ready`, `home_hub_idle` (UC-H03), `cl_send` (UC-CL06), or `course` detail (UC-C06).
- **Preconditions:** Authenticated parent JWT; child profile selected; one device claimed and online; entitlement check passes (active sub or one-time purchase); no `parent_stop_cooldown_until` active.
- **Main Flow:**
  1. ParentApp POSTs `/v1/sessions/start` with `{user_id, child_id, device_id, course_id, X-Request-Id, Idempotency-Key}` per sequence `docs/sequences/04-realtime/session-start-mobile.sequence.mmd`.
  2. RealtimeService runs entitlement check (sys-19) + cooldown check (`users.parent_stop_cooldown_until`); creates `realtime_sessions` row state=`CONNECTING`, state_version=0; allocates `device_session_id` UUID.
  3. RealtimeService MQTT-publishes `device/{device_id}/sessions/start` with the new session metadata.
  4. Server returns 200 with `{session_id, device_session_id, expires_at}` to ParentApp.
  5. Robot (sys-03 RuntimeApp) subscribes the MQTT topic, opens WS to `wss://realtime/v1/session/{session_id}` per existing `docs/sequences/04-realtime/ws-handshake.sequence.mmd`.
  6. ParentApp opens read-only observer WS to `wss://realtime/v1/observer/{session_id}` per sequence `docs/sequences/04-realtime/observer-attach.sequence.mmd`; receives initial state snapshot.
  7. ParentApp transitions to `cl_running` (or CompanionScreen) showing live mirror via observer events: `session.started`, `turn.created`, `safety.halt`, `session.reconnecting`, `session.resumed`, `session.end {end_reason}`.
  8. Lesson runs robot-side per UC-L01..L21 (see ADR-0006 D5 — phone-runtime lesson-session screens are demo-only behind `__USE_PHONE_RUNTIME__` flag in production).
  9. On terminal event, ParentApp surfaces appropriate post-lesson UX: `lesson_summary` (UC-P03) for success, `parent_stopped` / `timed_out` / `cost_capped` / `abandoned_disconnect` overlay screens for terminals.
- **Postconditions:** `realtime_sessions` row in terminal state; parent app observer lane closed cleanly; phone is free to navigate away during ACTIVE without affecting the conversation (ADR-0006 D7).
- **Alt Flow:**
  1. Parent puts phone down mid-session → observer lane idles; lesson continues on robot. On phone return, ParentApp re-attaches observer + receives state snapshot.
  2. Multi-device observer: a second parent device (or web dashboard) attaches observer for same session_id — both receive identical event stream.
- **Error Flow:**
  1. `device_offline` 409 → "Robot is offline" banner; suggest UC-F01 troubleshooting.
  2. `device_busy_other_session` 409 (unique partial index conflict) → "Robot is in another lesson"; offer "End current and start" flow (requires parent JWT freshness).
  3. `entitlement_check_failed` 402 → navigate to UC-SUB05 or UC-CL03 depending on entitlement source.
  4. `parent_stop_cooldown_active` 423 → "Robot was stopped; available again in N minutes" toast; suggest UC-PR05 safety dashboard.
  5. `idempotency_replay_410` (stale key against non-OPEN session) → client mints fresh Idempotency-Key + retries once per ADR §4.2 + audit C5.
- **Related:** LessonSession SM (`.omc/plans/state-machines-mobile-ux.md` §2.2); ADR-0006 ownership; existing UCs UC-L01..L21 are device-driven downstream; CompanionScreen UC-CL09 owns the parent-mirror visual layer.
