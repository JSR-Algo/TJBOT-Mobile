## UC-PR01 — Pass Parent Gate

- **Goal:** A user proves they are an adult (or at least can read 3-digit numbers) before entering parent-only surfaces.
- **Trigger:** Any UC that has `[requires] parent-gate : UC_PG_PASS` in its puml notes (UC-H08, UC-CL01, UC-PR02, UC-DP01, UC-RM01) navigates to `parent_gate`.
- **Preconditions:** User is on `parent_gate`; auth status is at least `authenticated` (per overview puml: only AuthUser-derived actors reach this screen).
- **Main Flow:**
  1. `ParentGatePage` mounts and generates a random 3-digit number (`ParentGateScreen.jsx:7`).
  2. User reads the number on screen.
  3. User types the number into the input field.
  4. On match, the screen auto-advances to `parent_summary` after a 280ms delay (`ParentGateScreen.jsx:11`).
- **Postconditions:** User lands on the destination of the gate (`parent_summary` for the default flow; other consumers redirect to their own destinations). No auth-store mutation occurs (gate is a speed-bump, not RBAC — KD4).
- **Alt Flow:**
  1. User taps "Back to play" → returns to `home_hub_idle` without unlocking the parent surface.
