## UC-BU01 — View Robot Overview

- **Goal:** Parent gets a high-level introduction to the TBOT robot product, building purchase intent before exploring details.
- **Trigger:** Parent taps "Buy TBOT" / "Get started" CTA from `home_hub_idle` or the marketing entry point.
- **Preconditions:** Parent is authenticated; app is connected.
- **Main Flow:**
  1. `RobotOverviewPage` mounts and renders static hero content (product image, headline, key selling points).
  2. "How it works" CTA navigates to UC-BU02.
  3. "Buy now" skip CTA can jump directly to UC-BU04 (bundle selection).
- **Postconditions:** Parent is on the discovery funnel entry screen; no state mutations.

---

## UC-BU02 — View How It Works

- **Goal:** Parent understands the product's learning methodology and interaction model before committing to purchase.
- **Trigger:** Parent taps "How it works" from UC-BU01 (`RobotOverviewPage`). Puml edge: `UC_BUY_INTRO ..> UC_BUY_HOW`.
- **Preconditions:** UC-BU01 has been displayed; no API call required.
- **Main Flow:**
  1. `HowItWorksPage` mounts with static step-by-step illustration content.
  2. Parent scrolls through 3–4 illustrated steps (robot interaction, voice lessons, progress tracking).
  3. "What's included" CTA navigates to UC-BU03.
- **Postconditions:** Parent has seen the methodology overview; no state mutations.

---

## UC-BU03 — View What's Included

- **Goal:** Parent reviews the physical and digital contents of the TBOT bundle before making a selection.
- **Trigger:** Parent taps "What's included" from UC-BU02. Puml edge: `UC_BUY_HOW ..> UC_BUY_INC`.
- **Preconditions:** UC-BU02 has been displayed; no API call required.
- **Main Flow:**
  1. `WhatsIncludedPage` mounts with static list of bundle items (robot unit, accessories, initial course credits).
  2. Parent scrolls through the item list with icons and descriptions.
  3. "Choose your bundle" CTA navigates to UC-BU04.
- **Postconditions:** Parent has reviewed the bundle contents; no state mutations.

## UC-BU04 — Pick Bundle

- **Goal:** Parent selects the hardware bundle configuration (e.g. starter vs. premium) that fits their needs.
- **Trigger:** Parent taps "Choose your bundle" from UC-BU03, or taps the "Buy now" skip CTA from UC-BU01. Puml edge: `UC_BUY_INC ..> UC_BUY_BUNDLE`.
- **Preconditions:** Parent is authenticated; bundle options are available in the purchase store.
- **Main Flow:**
  1. `PickBundlePage` mounts and renders available bundle options (price, contents summary, recommended badge).
  2. Parent taps a bundle card to select it; selection is reflected in `usePurchaseStore`.
  3. "Next" CTA navigates to UC-BU05.
- **Postconditions:** Selected bundle is stored in `usePurchaseStore`; navigation advances to subscription selection.

---

## UC-BU05 — Pick Subscription

- **Goal:** Parent selects a subscription plan (monthly / annual) to accompany the hardware bundle.
- **Trigger:** Parent taps "Next" after bundle selection in UC-BU04. Puml edge: `UC_BUY_BUNDLE ..> UC_BUY_SUB`.
- **Preconditions:** A bundle has been selected (UC-BU04 complete); `usePurchaseStore.orderId` is null (no active order yet).
- **Main Flow:**
  1. `PickSubscriptionPage` mounts and renders subscription options with price comparison.
  2. Parent taps a plan card; selection is stored in `usePurchaseStore`.
  3. "Next" CTA navigates to UC-BU06.
- **Postconditions:** Subscription plan is stored; navigation advances to privacy review.

---

## UC-BU06 — Review Privacy & Trust

- **Goal:** Parent reads the privacy policy and COPPA compliance summary before confirming their purchase, satisfying informed-consent requirements.
- **Trigger:** Parent taps "Next" after subscription selection in UC-BU05. Puml edge: `UC_BUY_SUB ..> UC_BUY_PRIV`.
- **Preconditions:** Bundle and subscription are selected; no API call required for this screen.
- **Main Flow:**
  1. `ReviewPrivacyPage` mounts with static privacy summary and a link to the full privacy policy (opens in-app browser).
  2. Parent reads the summary; "I agree" checkbox must be checked to enable "Proceed to checkout".
  3. Tapping "Proceed to checkout" navigates to UC-BU07.
- **Postconditions:** Privacy consent is recorded locally; navigation advances to checkout. No server call yet.

## UC-BU07 — Place Order / Checkout

- **Goal:** Parent confirms the order summary and initiates the checkout, which creates the order record and presents payment options.
- **Trigger:** Parent taps "Proceed to checkout" from UC-BU06. Puml edge: `UC_BUY_PRIV ..> UC_BUY_CHECKOUT`.
- **Preconditions:** Bundle, subscription, and privacy consent are confirmed; `usePurchaseStore.paymentStatus === 'idle'`.
- **Main Flow:**
  1. `CheckoutPage` mounts and renders order summary (bundle, subscription, price total).
  2. Page calls `createOrder()` from `src/services/api/purchase.api.js` with an idempotency key (`http/idempotency.js` — puml note).
  3. On success, `usePurchaseStore.startCheckout(orderId)` is called; payment options appear.
  4. Parent chooses Apple Pay (UC-BU08) or Card (UC-BU09) via extend flows.
- **Postconditions:** Order is created server-side; `usePurchaseStore.orderId` is set; `paymentStatus` is `'pending'`.
- **Alt Flow:**
  1. `createOrder` returns an error → show order-creation failure with retry CTA; `paymentStatus` stays `'idle'`.

## UC-BU08 — Pay with Apple Pay

- **Goal:** Parent completes payment via Apple Pay, delegating the transaction to the Apple Pay provider.
- **Trigger:** Parent taps "Apple Pay" payment option on `CheckoutPage`. Puml edge: `UC_BUY_CHECKOUT ..> UC_BUY_APPLE` (extend).
- **Preconditions:** Order is created (`usePurchaseStore.orderId` non-null); Apple Pay is available on device; payment provider identity NOT CONFIRMED IN SOURCE (KD9 — all backend cells sentinel).
- **Main Flow:**
  1. App triggers the Apple Pay payment sheet via the platform API.
  2. Parent authorises payment via Face ID / Touch ID.
  3. On provider success, app calls `processPayment()` from `src/services/api/purchase.api.js` to record the result.
  4. `usePurchaseStore.confirmPayment()` is called; navigation advances to UC-BU10.
- **Postconditions:** Payment confirmed; `usePurchaseStore.paymentStatus === 'confirmed'`; navigates to order confirmation.
- **Alt Flow:**
  1. Parent cancels Apple Pay sheet → returns to `CheckoutPage`; `paymentStatus` stays `'pending'`.
  2. Payment declined → show decline message with retry and card-pay fallback options.

## UC-BU09 — Pay with Card

- **Goal:** Parent completes payment by entering card details, delegating the transaction to the payment provider.
- **Trigger:** Parent taps "Pay with card" payment option on `CheckoutPage`. Puml edge: `UC_BUY_CHECKOUT ..> UC_BUY_CARD` (extend).
- **Preconditions:** Order is created (`usePurchaseStore.orderId` non-null); payment provider identity NOT CONFIRMED IN SOURCE (KD9 — all backend cells sentinel).
- **Main Flow:**
  1. `CardPayPage` or in-checkout card form mounts and renders card number, expiry, and CVV fields.
  2. Parent enters card details; client-side validation runs on blur.
  3. On "Pay" tap, app calls `processPayment()` from `src/services/api/purchase.api.js`.
  4. `usePurchaseStore.confirmPayment()` is called on success; navigation advances to UC-BU10.
- **Postconditions:** Payment confirmed; `usePurchaseStore.paymentStatus === 'confirmed'`; navigates to order confirmation.
- **Alt Flow:**
  1. Card declined → show decline message with re-entry affordance; `paymentStatus` stays `'pending'`.
  2. Validation failure → inline field errors; submit blocked until corrected.

## UC-BU10 — View Order Confirmation

- **Goal:** Parent receives confirmation that their order was placed successfully and understands the next steps (shipping timeline).
- **Trigger:** Payment succeeds (UC-BU08 or UC-BU09); `usePurchaseStore.paymentStatus === 'confirmed'`. Puml edge: `UC_BUY_CHECKOUT ..> UC_BUY_CONFIRM`.
- **Preconditions:** `usePurchaseStore.orderId` is set; `paymentStatus === 'confirmed'`.
- **Main Flow:**
  1. `OrderConfirmationPage` mounts and calls `getOrder()` from `src/services/api/purchase.api.js` using the stored `orderId`.
  2. UI renders order ID, itemised summary, estimated delivery date, and shipping address.
  3. "Track my order" CTA navigates to UC-BU11.
- **Postconditions:** Confirmation displayed; order data persisted server-side.

---

## UC-BU11 — Track Shipping

- **Goal:** Parent monitors the delivery status of their TBOT robot after order is placed.
- **Trigger:** Parent taps "Track my order" from UC-BU10, or re-enters the purchase domain after order is placed. Puml edge: `UC_BUY_CONFIRM ..> UC_BUY_SHIP`.
- **Preconditions:** `usePurchaseStore.orderId` is set; `getShippingStatus()` API is reachable.
- **Main Flow:**
  1. `TrackShippingPage` mounts and calls `getShippingStatus()` from `src/services/api/purchase.api.js`.
  2. UI renders shipping status timeline (ordered → shipped → out for delivery → delivered).
  3. `usePurchaseStore.setShipping(status)` is updated with the latest status.
  4. When status is `'delivered'`, a "My robot arrived!" CTA appears → UC-BU12.
- **Postconditions:** Shipping status displayed and stored in `usePurchaseStore.shippingStatus`.

## UC-BU12 — Confirm Robot Arrived

- **Goal:** Parent confirms that the physical robot has been received, unlocking the activation flow.
- **Trigger:** Parent taps "My robot arrived!" from UC-BU11, or shipping status transitions to `'delivered'`. Puml edge: `UC_BUY_SHIP ..> UC_BUY_ARRIVED`.
- **Preconditions:** `usePurchaseStore.shippingStatus === 'delivered'` (or parent self-reports arrival).
- **Main Flow:**
  1. `RobotArrivedPage` mounts with a prompt: "Got it? Let's set it up!"
  2. Parent taps "Start setup" → navigates to UC-BU13.
- **Postconditions:** Parent has confirmed receipt; navigation advances to activation.

## UC-BU13 — Activate Robot with Code

- **Goal:** Parent pairs the physical robot with their account by entering the activation code printed on the device, delegating confirmation to the robot device actor.
- **Trigger:** Parent taps "Start setup" from UC-BU12. Puml edge: `UC_BUY_ARRIVED ..> UC_BUY_ACTIVATE`.
- **Preconditions:** Robot is powered on; parent has the printed activation code. `activateRobot()` API is reachable.
- **Main Flow:**
  1. `ActivateRobotPage` mounts with an input field for the activation code.
  2. Parent enters the code (format: alphanumeric, 6–8 characters).
  3. On "Activate" tap, app calls `activateRobot()` from `src/services/api/purchase.api.js` with the code.
  4. `activateRobot()` delegates to Robot actor (puml: `UC_BUY_ACTIVATE ..> Robot : <<delegate>> (activation code)`).
  5. On success, navigation advances to UC-BU14.
- **Postconditions:** Robot is linked to the parent's account; activation state is persisted server-side.
- **Alt Flow:**
  1. Invalid or already-used code → inline error message; retry allowed.
  2. Robot not reachable / timeout → error with troubleshooting steps.

## UC-BU14 — Add First Course

- **Goal:** Parent adds the first course to the newly activated robot, completing the onboarding funnel and enabling the child's first lesson.
- **Trigger:** Robot activation succeeds (UC-BU13); app navigates to `purchase_first_course`. Puml edge: `UC_BUY_ACTIVATE ..> UC_BUY_FIRST`.
- **Preconditions:** Robot is activated; at least one course is available in the catalog.
- **Main Flow:**
  1. `AddFirstCoursePage` mounts with a curated list of starter courses.
  2. Parent taps a course card to select it.
  3. "Add to robot" CTA calls the course-library add flow (cross-domain edge → `UC_CL_ADDED`).
  4. On success, navigation exits to course-library or home (puml exit note: `[exit] → course-library : UC_CL_ADDED | UC_CL_BROWSE`).
- **Postconditions:** First course is added to the robot; purchase funnel is complete. `usePurchaseStore.reset()` may be called to clear transient order state.
