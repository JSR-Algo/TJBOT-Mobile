# i18n tooling — TBOT prototype

Scripts for the Path B (prototype-scoped) i18n migration. All scripts are plain
Node ESM. The fixture runner uses `jsdom` (resolved from any reachable
`node_modules/`); everything else is dependency-free. Run from the project root.

## Files

```
locales/
  en.json              EN catalog. Source of truth for "translatable strings".
  vi.json              VI catalog. Persona-aware (string OR {child, parent}).
  vi-pseudo.json       Generated. Wraps every value in [ŁĐ … ŁĐ] (or [≡ … ≡] when EN==VI).
  vi-stretched.json    Generated. +35% length pad with VN diacritics.
  legacy-inline.json   Verbatim snapshot of the v1 inline DICT. AC16 rollback target.

scripts/i18n/
  scan-hardcoded.mjs       AST-lite scan for translatable strings not in en.json.
                           Supports --files <a.jsx,b.jsx> for per-batch gating.
  check-key-parity.mjs     keys(en) === keys(vi); empty values; persona-incomplete; case-fold dups.
  check-register.mjs       Lints {child, parent} register quality (AC10).
  check-format-leaks.mjs   Greps for $-in-JSX-text and toLocale*(undefined,...) (AC11).
  check-fixtures.mjs       jsdom-based fixture runner (AC4/5/6/7/8/12/13).
  coverage-report.mjs      Aggregates state into coverage-report.json (AC14).
  pseudo-locale.mjs        Builds vi-pseudo.json (recurses persona objects).
  length-stress.mjs        Builds vi-stretched.json (recurses persona objects).
  expected-fixtures.json   Per-screen jsdom fixture manifest.
  .i18n-allowlist          Strings the scanner intentionally ignores.
  last-scan.json           Generated by scan --report.
  coverage-report.json     Generated by coverage-report.mjs.
```

## Commands

```bash
# Scan source for hardcoded UI strings
node scripts/i18n/scan-hardcoded.mjs                       # all P0-P5 files
node scripts/i18n/scan-hardcoded.mjs --files screens.jsx,home.jsx
node scripts/i18n/scan-hardcoded.mjs --report              # writes last-scan.json
node scripts/i18n/scan-hardcoded.mjs --json                # machine-readable

# Catalog quality
node scripts/i18n/check-key-parity.mjs
node scripts/i18n/check-register.mjs

# Format leaks (currency / undefined locale)
node scripts/i18n/check-format-leaks.mjs

# Fixture runner (jsdom)
node scripts/i18n/check-fixtures.mjs                       # all fixtures, vi+en
node scripts/i18n/check-fixtures.mjs --files purchase.jsx
node scripts/i18n/check-fixtures.mjs --locale vi-pseudo --leak

# Verification locales (regenerate before stress runs)
node scripts/i18n/pseudo-locale.mjs                        # writes vi-pseudo.json
node scripts/i18n/length-stress.mjs                        # writes vi-stretched.json

# Coverage snapshot
node scripts/i18n/coverage-report.mjs                      # writes coverage-report.json
```

## Full gate aggregator (Phase 10 sign-off)

```bash
node scripts/i18n/scan-hardcoded.mjs && \
node scripts/i18n/check-key-parity.mjs && \
node scripts/i18n/check-register.mjs && \
node scripts/i18n/check-format-leaks.mjs && \
node scripts/i18n/check-fixtures.mjs && \
node scripts/i18n/coverage-report.mjs
```

All exit codes must be 0.

## Verification locales (in-browser)

Open the prototype, then in DevTools console:

```js
localStorage.setItem('tbot.lang', 'vi-pseudo');     location.reload();
localStorage.setItem('tbot.lang', 'vi-stretched');  location.reload();
localStorage.setItem('tbot.lang', 'vi');            location.reload();
__tbot.useLegacyDict();   // re-enter v1 inline DICT path (rollback)
__tbot.reloadCatalog();   // exit legacy mode, refetch locales/{vi,en}.json
```

- `vi-pseudo` — every translated value is bracketed `[ŁĐ … ŁĐ]`. `[≡ … ≡]`
  marks identity translations (EN === VI), making AC7 leaks easy to spot.
- `vi-stretched` — every value padded to 1.35× length. Any clipped CTA /
  overflowing pill / truncated body = layout regression.

## Persona conventions

VI catalog values are either a flat string or `{child, parent}`. Walker resolves
persona via nearest ancestor `[data-persona]`, default `parent`. `check-register.mjs`
enforces:

- both `child` and `parent` non-empty
- `child !== parent`
- child contains ≥ 1 of {nhé, nha, nào, con, mình} (warn)
- parent contains NONE of those particles (warn)

## RTL / LTR

VI and EN are both LTR — no RTL handling required. Any future locale that flips
`<html dir>` will need a separate audit.

## Adding a new string (CONTRIBUTING)

1. Add the EN copy to `locales/en.json` (key === EN literal).
2. Add the VI translation to `locales/vi.json` — flat string OR `{child, parent}`
   per audit § e.
3. If the string is brand/content/proper-noun, add it to `.i18n-allowlist` instead.
4. Run the per-batch gate:
   ```
   node scripts/i18n/scan-hardcoded.mjs --files <touched.jsx>
   node scripts/i18n/check-key-parity.mjs
   node scripts/i18n/check-register.mjs
   ```
5. If you add `{child, parent}` to a key that already exists, also annotate the
   nearest JSX subtree with `data-persona`.

## Forward-port note

When `tbot-mobile/` migrates off Babel-standalone, replace this runtime walker
with `react-i18next` + namespaced keys (`surface.screen.element.state`) + ICU
plurals. Persona objects map to `react-i18next`'s `context` feature
(`t('lesson.cta.try_again', { context: 'child' })`). The `data-i18n-key` escape
hatch sites in this prototype are the natural seed for the namespaced key list.
